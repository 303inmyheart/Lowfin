# 1.1.3 — native discovery banner and startup readiness

The optional Movie discovery banner is a native HomeAdapter row, not injected JavaScript. Enable it in Home settings and reorder it with the existing semantic home-row ordering. It is disabled by default. Existing logical Resume/Next Up/recommendation/genre indices and cold-start first-Continue-card focus remain intact. Banner OK opens the current movie detail page; right requests a random permitted movie; left walks a maximum 20-item session history and opens the drawer at its beginning. Returning from details restores the displayed movie and banner focus using data-only home state.

Reuse authenticated Jellyfin Movie queries, the account-scoped metadata database, existing image loading/cache and aspect-preserving DetailLogo fallback. Posters are 2:3. Backdrops use a muted tint and dark overlay. Visible banner rotation is 15 seconds; slow backdrop zoom and small poster transitions honor the existing master animation switch. Rotation and zoom stop offscreen, without window focus, in the drawer or on detach. Only one random request can run per history; a bounded request falls back to local cached movies on failure. No full-library scan, WebView, additional cache store or playback work is introduced.

Appearance contains a separate Startup logo switch, enabled by default. The existing Lowfin logo pulses subtly while normal loading proceeds underneath. Readiness requires successful fresh responses for BOTH Continue Watching and Next Up; cached rows alone never satisfy it. It additionally checks published visible shelves and pending visible artwork, not all offscreen shelves or the entire precache. This overlay never steals the normal first-card focus and does not replay on ordinary detail returns or home refreshes. Android TV playback deep links remain direct. Any remote action can dismiss it. A 15-second maximum prevents an offline server, missing image or failed request from trapping the user; thus this is a best-effort loading cover rather than an unbounded server-health gate.

Tests cover bounded movie history/filtering, snapshot independence, both fresh-row gates with cached data present, timeout escape, no focus theft/replay, banner geometry, native detail/back/down navigation and restored film identity. The complete existing suite must pass before delivery. Scope is only TV .128, no other TVs, shutdown or GitHub push.

A live-TV check exposed a banner poster opacity bug in the first installed candidate: ImageView.setAlpha(1) selected its deprecated integer overload, making the drawable 1/255 opaque even though the bitmap had loaded. The corrected candidate uses setAlpha(1f) for View opacity. The regression now verifies drawable alpha 255, nonempty mapped bounds and actual drawn artwork pixels, in addition to download completion. The existing ArtworkView and cache are retained.

The first full run passed 406 tests. A subsequent run exposed a timing-dependent existing synthetic navigation fixture (also passing in isolation): it accepted nonempty cached rows before fresh responses had drained, then replaced them with 40-card artificial rows. Its preparation now drains the initial general workers and their UI deliveries before installing the artificial rows. Production navigation was not changed for this test stabilization.
