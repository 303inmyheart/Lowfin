# 1.1.1 — independent home refresh and Companion update notices

Continue Watching and Next Up previously ran sequentially in one general content-worker task. A slow native Resume request or the additional Companion resume reconciliation delayed Next Up; occupied genre/recommendation workers could delay both. They now have two reserved, lazily started process workers and separate tasks, allowing either shelf to publish as soon as its own request/reconciliation completes. Preserve native request parameters, cached-first display, Companion completion/resume visibility, screen/account guards, refresh debounce and launcher publication. Stale queued screens are rejected before requesting data. No added polling, server changes, lower timeouts or previewing unverified native resume data ahead of Companion reconciliation. Existing cached rows remain available on failure.

Each successful incremental Companion batch can trigger a short toast. The switch is under Settings / Library and Cache, enabled by default, and appears only when incremental Companion support is detected. Both English and German strings are provided. The toast announces new metadata/image information received, not that image files have finished downloading. It uses existing committed journal deliveries only; no extra API calls. Ignore empty responses, history resets, baseline checks and repeated cursor values. Coalesce nearby batches into one notice after 1.5 seconds, without delaying metadata commit or cache handling. Check the setting, active foreground activities and current account/cache instance both when accepting and displaying a notice; retired instances cancel pending delivery. Notifications may appear during playback while the app is in the foreground and do not steal remote focus.

Tests block either Resume or Next Up while all four general content workers are occupied. The other row must show fresh server data before the blocked request is released, and the blocked row retains cached data until its response arrives. Existing cache/focus/Companion tests remain in the full suite. Notice tests cover grouping, empty polls, disabling/backgrounding, account retirement, the reversible switch/plugin-absent hiding, and actual incremental delivery through CacheChanges.

User authorization updated 2026-10-21: install completed builds directly, exclusively on 192.168.1.128 and open Lowfin afterward. Do not install on .87 or .166. The prior shutdown request applied to the completed 1.1.0 installation; no shutdown is requested for this release. No GitHub push.

Release verification and device results follow after build completion. No quantified server/TV speedup is claimed from blocked-request regression tests alone.
